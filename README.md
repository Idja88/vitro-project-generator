# vitro-project-generator

## Описание

Модуль «Генератор проектов» — веб-приложение, которое через REST API Vitro-CAD MP управляет структурой папок проекта в системе хранения данных (СХД): по матрице «объекты проектирования × марки комплектов» создаёт, удаляет в корзину и восстанавливает папки, копирует в них шаблоны, назначает права подразделениям и выгружает аналог Формы 10 в Excel.

Точка входа — «Вызов внешнего сервиса» из функционала «Действия»: кнопка доступна в списке «Реестр проектов».

## Возможности

- матрица выбора: добавление объектов площадки (включая «Общий объект» — марки прямо в папке проекта) и марок с номером раздела 1–99;
- перетаскивание строк и столбцов, порядок столбцов сохраняется в матрице;
- выделение строк и столбцов и удаление выделенного;
- предпросмотр перед сохранением: что будет создано, удалено в корзину, восстановлено;
- выгрузка Формы 10 по шаблону;
- работа от имени пользователя Vitro-CAD (токен из вызова действия, cookie на сутки).

## Архитектура

```
backend/    Flask (Python 3.12, uv): API /api/v1, логика СХД, раздача собранного фронтенда
frontend/   React + TypeScript (Vite, Mantine, TanStack Query, dnd-kit)
Dockerfile  один образ: React собирается в первой стадии, gunicorn отдаёт API и статику
```

| Адрес | Назначение |
|---|---|
| `POST /callback` | вызов из Vitro-CAD: ставит cookie с токеном, отвечает ссылкой на страницу проекта |
| `GET /project/<id>` | страница генератора (React) |
| `/api/v1/...` | JSON API для фронтенда |
| `GET /healthz` | проверка живости без авторизации |

## Разработка

Нужны [uv](https://docs.astral.sh/uv/) и Node.js 26 LTS.

```bash
# бэкенд: .env в backend/ по образцу .env.example, FLASK_CONFIG=dev
cd backend
uv sync
uv run flask --app vitro_generator run        # http://127.0.0.1:5000

# фронтенд: dev-сервер с горячей перезагрузкой, API проксируется на :5000
cd frontend
npm ci
npm run dev                                    # http://localhost:5173/project/<id>
```

В среде `dev` при заданных `VITRO_CAD_ADMIN_USERNAME` и `VITRO_CAD_ADMIN_PASSWORD` страница открывается без вызова из Vitro-CAD: приложение само получает токен через API.

Чтобы Flask отдавал фронтенд без Vite: `npm run build` в `frontend/`, затем открыть `http://127.0.0.1:5000/project/<id>`.

## Развёртывание

На сервере нужны Docker и nginx.

1. Положить рядом `docker-compose.yml` и `.env` (по образцу `.env.example`, `FLASK_CONFIG=prod`, `PREFIX=/generator`). Переменные `VITRO_CAD_ADMIN_*` на сервере не задавать.
2. Запустить:

   ```bash
   docker compose pull
   docker compose up -d
   ```

3. Проксировать `/generator` на контейнер:

   ```nginx
   location /generator {
       proxy_pass http://127.0.0.1:8000;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_read_timeout 300s;
   }
   ```

Обновление: указать версию в `GENERATOR_VERSION` в `.env` (или оставить `latest`) и повторить шаг 2. Откат — вернуть предыдущую версию.

## Настройка Vitro-CAD MP

### Списки

* project_list — Реестр проектов — плоский список, основная информация о проекте
* company_list — Реестр компаний — плоский список, информация о заказчике проекта
* object_list — Реестр объектов — иерархический список, информация об объектах заказчика
* sheet_set — Марки комплекта — плоский список, справочная информация о всех марках разделов
* sheet_package — Разделы — плоский список, справочная информация о всех разделах

### Списки, доступные по умолчанию

* document — Файлы — иерархический список, система хранения данных по проектам
* principal — Пользователи — иерархический список, список пользователей системы

### Типы элементов и их атрибуты

#### Карточка проекта (Реестр проектов)
* selection_matrix — Матрица выбора — данные в формате JSON
* is_created_by_generator — Создан генератором — флаг
* contract_list_lookup — Договор проекта — ссылка на элемент списка «Реестр договоров»
* object_list_lookup_tree — Площадка проекта — ссылка на элемент списка «Реестр объектов»
* project_code_auto — Код — вычисляемое поле (прежнее имя `code` тоже поддерживается)
* chief_project_engineer — ГИП — ссылка на элемент списка «Пользователи»

#### Карточка заказчика (Реестр объектов)
* company_customer_lookup — Заказчик — ссылка на элемент списка «Реестр компаний»

#### Карточка объекта (Реестр объектов)
* object_plan_number — Номер по генплану — целое число

#### Марка комплекта (Марки комплектов)
* code — Код — однострочный текст
* sheet_package_lookup — Раздел — ссылка на элемент списка «Разделы»
* principal_lookup — Подразделение — ссылка на элемент списка «Пользователи»
